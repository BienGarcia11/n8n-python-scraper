# RAG System with Semantic Cache

A production-ready web scraping RAG system that processes URLs, generates embeddings using OpenAI, and stores them in Supabase for semantic search. Deployed on Railway with automatic error handling and retry logic.

## Architecture Overview

```
┌─────────────────┐
│   n8n Webhook  │
│   (Monthly)     │
└────────┬────────┘
         │ POST /scrape
         ▼
┌─────────────────────────────────────┐
│  Railway (FastAPI Service)       │
│  - supabase_scraper.py           │
│  - Batch processing (3 URLs)      │
│  - Retry logic (3 attempts)       │
│  - Error handling                │
└────────┬────────────────────────┘
         │
         ├──────────────┬──────────────┐
         ▼              ▼              ▼
    ┌─────────┐   ┌──────────┐   ┌──────────────┐
    │ Supabase│   │  OpenAI  │   │   n8n Queue  │
    │ Database│   │   API    │   │   (url_queue)│
    └────┬────┘   └────┬─────┘   └──────────────┘
         │              │
         ▼              ▼
    ┌──────────────────────────┐
    │    documents table     │
    │  - content (text)     │
    │  - metadata (jsonb)   │
    │  - embedding (vector)  │
    │  - url (text)         │
    │  - chunk_index (int)   │
    │  - total_chunks (int)   │
    └──────────────────────────┘
```

## Features

### Core Capabilities
- **Queue-Based Processing**: Processes URLs from Supabase `url_queue` table
- **Parallel Processing**: Handles 3 URLs concurrently for efficiency
- **Retry Logic**: 3 attempts with exponential backoff (30s, 60s, 120s)
- **Full Refresh Strategy**: Deletes old chunks before inserting new ones
- **Detailed Logging**: Comprehensive console output for monitoring
- **Health Checks**: `/health` endpoint for monitoring service status

### Web Scraping
- **Versatile Scraper**: Handles multiple website types (blog, news, docs, ecommerce, Xero)
- **Dynamic Content**: Uses Playwright for JavaScript-rendered pages
- **Clean Output**: Structured extraction of headings, paragraphs, lists, links, code, images

### Embedding Generation
- **OpenAI text-embedding-3-small**: High-quality embeddings (1536 dimensions)
- **Smart Chunking**: 800-character chunks with 100-character overlap
- **Batch Processing**: 20 embeddings per API call for efficiency

### Database Integration
- **Supabase Vector Column**: `vector(1536)` for semantic search
- **Rich Metadata**: JSONB metadata with URLs, titles, authors, dates
- **Chunk Tracking**: Index and total chunks for each URL

## Database Schema

### url_queue Table
```sql
CREATE TABLE url_queue (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    url TEXT NOT NULL UNIQUE,
    status TEXT NOT NULL DEFAULT 'pending', -- pending, processing, completed, failed
    error_message TEXT,
    attempts INTEGER DEFAULT 0,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    processed_at TIMESTAMP WITH TIME ZONE
);

CREATE INDEX idx_url_queue_status ON url_queue(status);
```

### documents Table
```sql
CREATE TABLE documents (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    content TEXT NOT NULL,
    metadata JSONB,
    embedding vector(1536),
    url TEXT NOT NULL,
    title TEXT,
    chunk_index INTEGER,
    total_chunks INTEGER,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- Enable pgvector extension (run once)
CREATE EXTENSION IF NOT EXISTS vector;

-- Create vector similarity search index
CREATE INDEX idx_documents_embedding ON documents 
    USING ivfflat (embedding vector_cosine_ops) 
    WITH (lists = 100);

-- Add HNSW index for better performance
CREATE INDEX idx_documents_hnsw ON documents 
    USING hnsw (embedding vector_cosine_ops) 
    WITH (m = 16, ef_construction = 64);

CREATE INDEX idx_documents_url ON documents(url);
```

### RLS Policies (Recommended)

```sql
-- Enable RLS
ALTER TABLE documents ENABLE ROW LEVEL SECURITY;

-- Allow read access for authenticated users
CREATE POLICY "Public read access" 
ON documents FOR SELECT 
TO authenticated 
USING (true);

-- Allow inserts for service role
CREATE POLICY "Service insert" 
ON documents FOR INSERT 
TO service_role 
WITH CHECK (true);

-- Allow updates/deletes for service role
CREATE POLICY "Service modify" 
ON documents FOR ALL 
TO service_role 
USING (true);
```

## Setup Instructions

### 1. Local Development

**Clone and Install Dependencies:**
```bash
# Install Python dependencies
pip install -r requirements.txt

# Install Playwright browsers
playwright install chromium
```

**Configure Environment:**
```bash
# Copy example .env file
cp .env.example .env

# Edit .env and add your credentials
# SUPABASE_URL=your_supabase_url
# SUPABASE_KEY=your_supabase_key
# OPENAI_API_KEY=your_openai_api_key
```

**Run Locally:**
```bash
# Start the FastAPI server
python supabase_scraper.py

# Or use uvicorn directly
uvicorn supabase_scraper:app --host 0.0.0.0 --port 8000 --reload
```

### 2. Railway Deployment

**Step 1: Create Railway Project**
```bash
# Install Railway CLI
npm install -g @railway/cli

# Login to Railway
railway login

# Initialize project in current directory
railway init

# Link to existing Railway project (or create new)
railway link
```

**Step 2: Set Environment Variables**
```bash
# Add Supabase URL
railway variables set SUPABASE_URL=your_supabase_url

# Add Supabase Key
railway variables set SUPABASE_KEY=your_supabase_key

# Add OpenAI API Key
railway variables set OPENAI_API_KEY=your_openai_api_key
```

**Step 3: Deploy**
```bash
# Deploy to Railway
railway up

# Or deploy and stream logs
railway up --logs
```

**Step 4: Get Service URL**
```bash
# Get the deployed service URL
railway domain

# Your service will be available at:
# https://your-project-name.up.railway.app
```

## API Endpoints

### 1. Root Endpoint
```
GET /
```
Returns service status and version.

### 2. Health Check
```
GET /health
```
Returns health status including:
- Supabase connection
- OpenAI configuration

### 3. Process All URLs
```
POST /scrape
Content-Type: application/json

{
  "batch_size": 3  // Optional, default is 3
}
```
Processes all pending URLs in queue until empty.

**Response:**
```json
{
  "success": true,
  "message": "Scraping completed successfully",
  "total_processed": 15,

  "processing_time": "5m 23s",

  "new_urls": 7,
  "details": [
    {
      "url": "https://example.com/article",
      "status": "completed",
      "chunks": 22,
      "deleted_chunks": 22,
      "attempts": 1,
      "error": null

  ]
}
```

## Error Handling

### Retry Strategy
- **Attempt 1**: Immediate processing
- **Attempt 2**: Wait 30 seconds, retry
- **Attempt 3**: Wait 60 seconds, retry
- **Attempt 4**: Wait 120 seconds, retry
- **Final**: Mark as failed, record error message

### Common Errors

**Supabase Connection Error:**
```
Error: Supabase connection failed
Solution: Check SUPABASE_URL and SUPABASE_KEY in .env
```

**OpenAI API Error:**
```
Error: OpenAI API rate limit
Solution: Wait and retry (automatic with backoff)
```

**Scraping Timeout:**
```
Error: Page load timeout
Solution: Increase timeout in scraper_config or check URL
```

## Troubleshooting

### Issue: Service Won't Start
- Check environment variables are set correctly
- Verify Python version (3.8+)
- Ensure all dependencies installed

### Issue: URLs Not Processing
- Check URL status in url_queue table
- Verify Supabase credentials
- Check Railway logs for errors

### Issue: Slow Performance
- Reduce batch_size in API call
- Check database indexes
- Monitor OpenAI API usage

### Issue: High Railway Costs
- Use cron instead of always-on
- Optimize batch sizes
- Monitor and adjust retry timeouts

## Security Best Practices

1. **Never Commit .env**: Always keep API keys in environment variables
2. **Use Service Role Keys**: For database operations (not anon keys)
3. **Enable RLS**: Restrict database access
4. **Rotate Keys**: Regularly update API keys
5. **Monitor Logs**: Watch for unauthorized access
